# AI 辅助交付过程记录

## 1. 原始目标和约束

用户要求交付科学计算器 HTTP 后端，并验证候选人的需求分析、架构设计和 Java
工程能力。硬性约束包括：

- Java 17、Spring Boot 3、Maven、JUnit 5；
- 禁止数据库、Redis、第三方存储和缓存；
- 禁止外部接口调用；
- 仅提供 HTTP 后端；
- 输出可由 `java -jar` 启动的 runnable JAR；
- 采用 DDD，增加中文注释并规范格式；
- 数学规则必须可扩展，不能集中在单一计算类；
- 配置文件使用 YAML；
- 外部接口调用后必须在后台打印可检索的访问日志；
- 日志只能使用本地内存或有界淘汰策略，不引入日志中间件；
- 文档区分 AI 产出和候选人个人复核、优化内容。

## 2. AI 辅助需求分析

AI 将极简需求补充为以下可验收能力：

1. 提供计算、查询内存历史和清空历史三个 HTTP 用例；
2. 支持四则、取模、幂、一元正负号、科学函数、常量和科学计数法；
3. 三角函数采用度数制，幂运算右结合；
4. 增加数值积分和数值导数，验证新类别可以通过策略扩展；
5. 历史、表达式长度、请求体和嵌套深度均设上限；
6. 领域异常统一转换为稳定 HTTP 400 协议；
7. 数据仅存在 JVM 内存中，重启即清空。

## 3. AI 辅助架构设计

### DDD 分层

AI 设计并实现：

- 接口层：REST Controller、DTO、异常处理和请求过滤；
- 应用层：命令、结果视图和用例编排；
- 领域层：聚合根、值对象、仓储端口、领域服务和计算规则；
- 基础设施层：内存仓储、ID 生成器和 Spring 组合根。

### 可扩展计算内核

针对“多个计算方法集中在同一类”的问题，AI 将原实现替换为：

```text
ExpressionCalculationTemplate
  + PrattExpressionParser
  + ExpressionNode AST
  + AstEvaluationContext
  + CalculationRuleRegistry
  + 独立 Strategy
```

每个加、减、乘、除、取模、幂、一元运算、科学函数和常量都由独立规则类负责。
积分和导数也作为两个独立 `FunctionRule` 接入，核心模板没有相关条件分支。

## 4. AI 辅助编码与优化

AI 完成的主要代码工作：

- 将领域层和应用层保持为无 Spring 注解的纯 Java；
- 实现 Pratt 解析器并从注册表读取优先级和结合方向；
- 实现不可变变量求值上下文，为微积分提供重复 AST 求值能力；
- 实现四类小策略接口和重复注册快速失败机制；
- 将所有内置运算拆分为独立策略类；
- 使用 Simpson 法实现 `integral`，使用中心差分实现 `derivative`；
- 使用 `@Import` 在基础设施组合根中注册无框架注解的领域策略；
- 将 `application.properties` 替换为带中文说明的 `application.yml`；
- 为新增核心类和关键逻辑补充中文 JavaDoc；
- 将 Java、XML 和 YAML 展开为可读的多行格式；
- 新增全局 HTTP 访问日志 Filter、`X-Request-Id` 链路标识和 MDC；
- 根据状态码输出 `INFO`、`WARN` 或 `ERROR` 结构化控制台日志；
- 新增默认容量 1000 的有界内存日志滚动队列；
- 避免记录请求体、响应体、表达式和鉴权信息。

## 8. AI 自检、失败与修正记录

为保留真实交付过程，本轮没有隐藏中间失败：

1. 首次重构编译时，通用排序比较器的 Lambda 类型被 Java 推断为 `Object`；
   AI 将比较器参数显式标注为泛型 `T` 后重新执行完整构建。
2. 首次 REST 微积分测试使用 `closeTo` 直接匹配 JsonPath 返回的
   `BigDecimal`，产生测试类型不匹配；AI 使用 JsonPath 的 `Double.class`
   目标类型转换后重跑测试。
3. 修正后执行 `clean test package`，完成原有 19 个测试。
4. 增加 SRE 访问日志后，新增 3 个测试；最终 22 个测试全部通过，并对
   最终 JAR 进行真实 HTTP 和后台日志冒烟验证。

上述修正均属于 AI 生成代码后的自动校验和迭代，不应记录为候选人个人优化。


## 9. SRE 日志优化记录

### AI 产出

AI 识别到 Spring Boot 默认只输出启动和框架日志，没有应用级 HTTP access log，
因此新增全局 `HttpAccessLogFilter`。每次请求完成后输出 requestId、方法、路径、
状态码、耗时和客户端地址，并把同一条记录写入有界内存存储。

### AI 校验和优化

- 将访问日志 Filter 排在请求体大小过滤器之前，确保 413 请求也会被记录；
- 对调用方传入的 requestId 限制为 1～64 位安全字符，防止日志注入；
- 未传或传入非法 requestId 时生成 UUID；
- 在响应头返回 `X-Request-Id`，形成调用方到服务端的关联闭环；
- 不信任 `X-Forwarded-For`，直接记录 Servlet 提供的远端地址；
- 不记录正文、表达式、查询参数和鉴权头；
- 使用有界滚动队列而不是无界集合；
- 没有增加未鉴权的日志查询 REST 接口。
